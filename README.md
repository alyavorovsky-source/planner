# DailyFlow — планировщик дня

Текущая версия: **2.3.0** (15.11.2026)

Простой планировщик задач, который работает прямо в браузере: без сервера, без регистрации и без установки.
Все данные хранятся локально (`localStorage`) и никуда не отправляются.

## Возможности

- **Одна страница «Задачи»** — просроченные, сегодняшние, завтрашние и более поздние задачи в одном списке, с группировкой по срокам.
- **Быстрое добавление**: введите название в строку над списком и нажмите Enter — задача создастся на сегодня со средним приоритетом.
- Полная форма задачи (кнопка «Добавить задачу» вверху): дата, время, категория, приоритет, статус, повторение, напоминание.
- **Статусы**: Новая, В работе, Приостановлено, Заблокировано, Отложена, Выполнена, Отменена. Меняются прямо в карточке, в форме задачи или перетаскиванием в канбане. «Выполнена» связана с галочкой: отметка в карточке и статус всегда согласованы.
- **Канбан**: переключатель «Список / Канбан» над списком задач. Колонки — статусы, карточки можно переносить между ними, удерживая левую кнопку мыши. Выбранный режим запоминается.
- Фильтры по статусу, категории и приоритету, сортировка, главные задачи дня (до трёх).
- **Свободные комментарии** — лента заметок без привязки к дню: добавление, правка, удаление.
- Календарь (месяц / неделя / день), привычки, статистика, архив.
- Светлая и тёмная темы, экспорт и импорт данных в JSON.
- Удобно на телефоне: меню разделов открывается кнопкой ☰, из настроек можно вернуться кнопкой «Назад».
- Окно «Что нового» показывается один раз после обновления; открыть его снова можно, нажав на номер версии.
- **Установка как приложение (PWA)** и работа без интернета.

## Запуск

Откройте `index.html` в браузере — больше ничего не нужно.

## Установка как приложение (PWA)

Установка работает только по **HTTPS** (например, на GitHub Pages) или на `localhost`. Если открыть `index.html` как локальный файл, Chrome скажет, что установить приложение нельзя, — это ограничение браузера.

1. Откройте адрес сайта в Chrome на телефоне.
2. Меню ⋮ → **Установить приложение** (или **Добавить на главный экран**).
3. На компьютере: значок установки в правой части адресной строки.

После первого открытия планер запускается и без интернета. Данные хранятся на устройстве.

## Публикация на GitHub Pages

1. Загрузите файлы в репозиторий (в корень, `index.html` должен лежать в корне).
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
3. Выберите ветку `main` и папку `/ (root)`, нажмите **Save**.
4. Через минуту-две сайт будет доступен по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

> Данные хранятся в браузере и привязаны к адресу сайта: на локальном `file://` и на GitHub Pages это будут разные хранилища. Чтобы перенести задачи, используйте экспорт/импорт JSON в настройках.

## Структура

```
index.html        — страница приложения
manifest.webmanifest — описание приложения для установки (название, иконки, цвета)
sw.js             — service worker: кэш для работы без интернета
icons/            — иконки приложения (192, 512, maskable, apple-touch)
style.css         — стили
js/utils.js       — вспомогательные функции
js/icons.js       — иконки
js/version.js     — версия, дата и история изменений (источник для окна «Что нового» и версии кэша)
js/store.js       — данные, статусы и работа с localStorage
js/views.js       — отрисовка разделов
js/comments.js    — свободные комментарии
js/whatsnew.js    — окно «Что нового»
js/pwa.js         — регистрация service worker
js/app.js         — навигация, формы, события
```

## Как выпустить новую версию

1. Откройте `js/version.js`, добавьте новую запись **в начало** списка `CHANGELOG`: номер версии, дату и список изменений.
2. Загрузите изменённые файлы в репозиторий. Версия в меню и настройках обновится сама, кэш для работы без интернета обновится вместе с ней, а окно «Что нового» один раз покажется всем, кто открыл новую версию.
3. Добавьте такую же запись в раздел «История изменений» ниже.
